# Library Overview
This PowerShell script, named `Clear-TextArtifacts.ps1`, is designed to 
process text files by removing ANSI escape sequences and other terminal 
artifacts that may be present within the content of markdown or plain 
documents (.md, .txt) but not binary Word documents (DOCX). The primary 
purpose of this script is to clean up these files so they can be used as 
intended without any unwanted formatting elements.

## Objects & Data Structures
No custom objects are defined within the provided code snippet; it uses 
built-in types and functions from PowerShell's standard library, 
particularly for handling file I/O operations and string manipulation. 
However, we can describe important aspects of these operations:

# Functions
### Clear-TextArtifacts(String $Text)
The `Clear-TextArtifacts` function takes a single text input (`$Text`) as 
its parameter and returns the cleaned version of this string with escape 
sequences removed. It uses regular expressions to identify and replace 
patterns representing terminal artifacts, ensuring that only visible 
are retained while escapes are stripped away.

- Parameter: `$Text (string)` - The text content from which ANSI escape 
sequences need to be cleaned out.
    - Returns a string with escaped characters removed. No return type 
specified as it is simply the modified input passed back.
### Test-BinaryDocument(String $Path)
The `Test-BinaryDocument` function attempts to detect binary Word files 
reading their headers and determines if they are OLE2 or ZIP format 
documents, which should not be cleaned due to potential data corruption. 
It accepts a file path as input.

- Parameter: `$Path (string)` - The full system path of the document that 
needs to have its binary nature confirmed before any processing is 
attempted.
    - Returns boolean (`$true` or `$false`) indicating whether detected 
text appears to be from an OLE2/ZIP archive, which are not supported by 
this script. If true, these files will be skipped over and a warning 
logged instead of processed.

## Code Explanation Segments (not complete functions)
### ANSI Escape Sequence Patterns
The regex patterns defined for identifying escape sequences within the 
text (`$ansiPattern` and `$literalEscPattern`) are:
- `x1B(?:[@-Z\\-_]|\[[0-?]*[ -/]*[@-~])`: Matches a wide range of ANSI 
codes, which begin with ESC (\x1B) followed by an escape character 
sequence.
- `"ESC\[[0-9;]*[a-zA-Z]"`: Recognizes specific escaped sequences that 
represent formatting instructions when typed directly into the terminal 
(e.g., ` for blue text).

### Regular Expression Used in Cleaning Text (`$cleanPattern`)
The regular expression used to remove one or more artifacts, potentially 
preceded by a word is: `(?:[^\s\x1B]+[ \t]*)?(?:$artifact)+`
- This allows for the removal of ANSI escape sequences and any directly 
preceding non-whitespace characters. If an escaped sequence starts at the 
beginning of a line, only that sequence will be removed.

## File Processing Logic Overview
The script processes files by first determining if they are text or 
documents using `Test-BinaryDocument`. It skips any detected binary 
document as it could corrupt plain text upon conversion. If the file is a 
directory, and not just one specific file:
- Recursively examines each supported extension within.
- Calls `Clear-TextArtifacts` on each found `.md`, `.txt`, or (in some 
environments) `.doc` files while processing individual text artifacts as 
described above. This is done in a non-destructive manner, with changes 
saved back to the original file only if an output path (`$OutputPath`) 
different from the input file's location was specified.

### Handling Binary Documents and Non-existent Paths
The script contains safeguards for these cases:
- If a binary document is detected, it logs a warning to indicate that 
such documents should not be processed by this tool. It exits early 
without attempting any cleaning.
- If the provided file path does not exist or if an invalid directory 
structure (non-directory when expected) is given, error messages are 
displayed and script termination occurs with appropriate logging.

## Notes on Usage
Users should ensure that they do not attempt to process binary files as 
this can result in data corruption. Additionally:
- It's important for the `$OutputPath` parameter to be used when saving 
changes, otherwise modifications are overwritten (`$FilePath`). This is a 
default behavior set by an `if ($isDirectory)` check.
- When running on directories with hidden files or special characters 
(e.g., spaces and tabs) within file names that could affect the 
`$cleanPattern`, users should verify they're compatible, as this script 
assumes basic ASCII naming conventions without additional whitespace 
handling in these cases.
- The `Get-Content` cmdlet is used to read input text with raw content 
(`-Raw`), which simplifies processing and avoids encoding issues within 
strings. This may not be suitable for all scenarios where preserving file 
integrity through character encodings matters, so adjustments could be 
necessary based on specific requirements.

### Dependencies and Compatibility Notes
The script's functionality is limited to text files with ANSI escape 
sequences that should appear plain. It assumes a Unix-like interpretation 
of these codes as part of the standard terminal escapes but does not 
extend beyond this scope without explicit detection logic or additional 
parsing mechanisms.
