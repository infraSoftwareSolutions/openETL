# Library Overview: PowerShell Wrapper for cppcheck Static Analysis Tool

This library provides a command-line interface wrapper around the 
`cppcheck` static analysis tool to facilitate code quality checks within 
Windows PowerShell. It primarily handles C/C++ source files but is 
designed with extensibility in mind, allowing easy adaptation for other 
languages and tools by modifying input parameters.

## Objects & Data Structures

No objects or data structures are defined outside of the functions 
themselves; they operate on strings representing file paths. The main 
purpose served here appears to be static code analysis rather than 
structured data storage, which is why no complex object representations 
like arrays or hashtables have been explicitly created.

## Functions

The script contains three primary function definitions that invoke the 
cppcheck tool with various configurations and input parameters for C/C++ 
source files. Below are their descriptions along with details on members, 
purposes, return values, and any important notes:

1. `Invoke-CCheckLib` (shortened as `Invoke-CPPCheck`) - Function 
Name:`Invoke-CCheckLib`. 
    **Description**: Analyzes C/C++ source files in a specified directory 
for warnings related to the standard C (`std=c11`), style, performance, 
and portability using cppcheck.
   **Parameters**:
      - `$IncludeDir` (type: `string`) The path to include directories 
used during analysis.
       *Description* It is mandatory as it tells `cppcheck`, where header 
files are located that might affect the code being analyzed, including 
system headers if specified.
      - `$TargetDir` (type: `string`) Represents the directory containing 
source and object (.o) files for analysis.
       *Description* It is mandatory as it specifies what should be 
checked by cppcheck.
   **Returns**: The function does not explicitly return any value. 
However, output such as warnings from `cppcheck` are displayed in the 
PowerShell console after execution.
      - Note: Ensure that 'cppcheck' is installed and accessible via PATH 
or provide an absolute path to avoid potential errors.

2. `Invoke-CxxCheckLib` (shortened as `Invoke-CPPCheck`) - Function 
Name:`Invoke-CxxCheckLib`. 
    **Description**: Similar function for C++ source files, analyzing 
using cppcheck with an emphasis on the latest ISO standard (`std=c++20`).
   **Parameters**:
      - `$IncludeDir` (type: `string`) Same as above.
       *Description* It serves a similar purpose for C++ projects.
      - `$TargetDir` (type: `string`) As with the previous function, it 
specifies what to analyze within this directory. In addition, since 
cppcheck's configuration is set explicitly here, you may want to adapt 
arguments as needed based on your analysis requirements and project 
settings.
   **Return**: Same considerations apply; output generated by `cppcheck` 
will be displayed in the PowerShell console after execution.

3. `Invoke-CppCheckLib` (shortened as `Invoke-CPPCheck`) - Function 
Name:`Invoke-CppCheck`. 
    **Description**: Analyzes C/C++ source files using cppcheck but takes 
an array of include directories (`$Includes`) and a target file path 
(`$Target`).
   **Parameters**:
      - `$Includes` (type: `string[]`) An array containing paths to 
additional include directories.
       *Description* Additional includes can be specified beyond the 
system ones, allowing for more granular control over what headers are 
included during analysis. If empty or not provided, cppcheck defaults to 
including all necessary standard and local header files as required by 
`cppcheck`.
      - `$Target` (type: `string`) The specific source file path.
       *Description* It specifies which C/C++ code should be analyzed for 
potential issues. This can also include object (.o) files if provided in 
the directory.
   **Return**: Same considerations apply; output from cppcheck is 
displayed after execution, directly related to `$Target`.

## Code Snippet (PowerShell functions)
```powershell
function Invoke-CCheckLib {
    [CmdletBinding()]
    param(
        [Parameter(Mandatory=$true)] [string] $IncludeDir,
        [Parameter(Mandatory=$true)] [string] $TargetDir
    )

    $exe = 'cppcheck'
    if (-not (Get-Command $exe -ErrorAction SilentlyContinue)) {
        Throw "'$exe' not found in PATH. Install cppcheck or add it to 
PATH."
    }

    $args = @(
        '--std=c11',
        '--enable=warning,style,performance,portability',
        '-I', $IncludeDir,
        '--suppress=unusedFunction',
        '--suppress=missingInclude',
        '--suppress=missingIncludeSystem',
        $TargetDir
    )

    & $exe @args
}
```
Repeat similar patterns for `Invoke-CxxCheckLib` and `Invoke-CPPCheck`, 
with adjustments to parameters specific to each function's purpose.

## Notes on Usage:
The functions are designed as wrappers, simplifying the invocation of 
cppcheck. Ensure that you understand any implications or limitations 
associated with this tool before using it in your workflow—`cppcheck` can 
provide detailed output which may sometimes require additional context to 
interpret fully.

Additionally, ensure `cppcheck`'s compatibility with your project 
and standards; customizations like suppression rules 
(`--suppress=unusedFunction`) might be necessary. Always test changes in 
safe environment before applying them to production code due to the 
potential impact on software quality assurance processes.
```
Invoke-CCheckLib -IncludeDir "path/to/includes" -TargetDir 
"path/to/source_files"
```
